# Для чего нужен сопровождающий прувер

Модель предлагает доказательство. Lean проверяет, доказывает ли оно именно ваше утверждение. Прувер связывает эти шаги и сохраняет свидетельство: какую задачу дали, какой ответ получили, что сообщил Lean и от каких аксиом зависит результат.

Практический пример: вы формализуете правило игры «категорию нельзя записать дважды». В исходном Lean-проекте задаёте состояние и теорему. Помощник предлагает тело доказательства. Если он вместо этого докажет `True`, добавит неподтверждённую аксиому или оставит `sorry`, строгого принятия не будет. При отказе можно получить следующую попытку с диагностикой Lean.

Это полезно при изучении Lean, разработке формальных моделей и проверке ответов моделей. Вы получаете проверяемый шаг рассуждения, который можно открыть и повторить. Соответствие формальных определений замыслу человека требует отдельной проверки.

## Локальный чат в текущей версии main

В ридер встроен настоящий локальный чат. Запуск после настройки: `./start-reader.sh`. Qwen отвечает на текстовые вопросы; DeepSeek/LoRA остаются отдельным источником доказательств. В браузере видны условие и результат отдельной проверки Lean. [Установка и границы](LOCAL_CHAT_RU.md). Это дополнение к main; старый релиз v0.1.0-alpha.1 остаётся зафиксированным срезом проверяющего инструмента.

## Что входит в первый релиз

- Проверка готового тела доказательства в фиксированном контексте.
- Извлечение целей через синтаксис Lean, с namespace, секциями и предшествующими определениями.
- Отдельный инспектор типа и зависимостей `Lean.collectAxioms`.
- Раздельные статусы стандартного и условного доказательства, отказа и ошибки окружения.
- Отдельные каталоги попыток, исходные ответы, диагностика и контроль целостности файлов.
- Экспериментальное подключение локальной MLX-модели и LoRA с максимум тремя попытками.
- Самопроверка без модели, примеры и проверка GitHub Actions на macOS.

## Установка и первый запуск

Полная инструкция: [INSTALL.md](INSTALL.md). Установите Python 3.11 и Elan/Lake, затем:

```sh
git clone https://github.com/kernelpanic888/lean-proof-companion.git
cd lean-proof-companion
python3.11 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
lake env lean --version
lean-proof-companion doctor
lean-proof-companion verify --source examples/Tasks.lean \
  --name CompanionExample.twice_zero --proof examples/valid.proof
lean-proof-companion selftest
```

`accepted: true` означает принятие именно этой попытки по строгой политике. `CONDITIONAL` означает зависимость от пользовательских аксиом и не считается строгим успехом. Наличие предупреждения также запрещает строгий успех. Список аксиом берётся из окружения Lean, а не из текста, который напечатал кандидат.

Для сохранённого запуска:

```sh
lean-proof-companion replay runs/ИМЯ_КАТАЛОГА_ПОПЫТКИ
```

Эта команда проверяет хеши. Чтобы повторить проверку ядром, снова выполните `verify` с сохранёнными задачей и доказательством; появится новый запуск. Старый каталог не перезаписывается.

## Честные границы

Первый релиз предварительный. Проверка и примеры без модели входят в приёмку. Путь генерации проверен на одной маленькой задаче с настоящими Base и LoRA в существующем MLX-окружении: Base получил отказ, LoRA — строгое принятие. Оба ответа достигли лимита 512 токенов. Это проверка подключения, а не независимая оценка модели; свежая установка ML-окружения не проверена. Обучение, веса, рабочий адаптер и независимый бенчмарк сюда не входят.

Исторические 10/10 относились к готовым исходным доказательствам, 5/10 — к другому локальному прогону модели со строгой политикой предупреждений. Эти числа не являются результатами данного релиза и не доказывают качество модели. Независимой оценки модели здесь нет.

Родительский проект остаётся `NEEDS_REWORK`: его полный план из 18 замечаний, формализация переходов MG-01, 50000 партий, новый датасет и независимые задачи не объявлены завершёнными. Публикация этого инструмента не меняет этот статус.

Проверенный путь исполнения — macOS. Окружение Lean и исходная задача должны быть доверенными. Ограничение записи и сети не запрещает чтение всех файлов компьютера; для чужого потенциально вредоносного кода используйте отдельную машину без секретов. Подробности: [SECURITY.md](../SECURITY.md).

## Проверить полезное правило

В `examples/NoDoubleWrite.lean` есть небольшой пример счётной карточки: 13 категорий и запрет повторной записи уже занятой категории. Границы категории заданы типом `Fin 13`.

```sh
lean-proof-companion verify --source examples/NoDoubleWrite.lean \
  --name Scorecard.no_double_write --proof examples/no-double-write.proof
```

Lean проверяет именно это правило в данной небольшой модели. Связь с настоящим игровым движком потребует отдельной проверки соответствия.
